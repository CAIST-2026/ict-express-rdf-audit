# Statistical analysis (revision Stage 5)

## 1. What was recomputed

The statistical package consolidates four evidence streams:

1. Phase 1 500-query paired tests (`phase1_500`).
2. Revision matched-supervision contrasts (`revision_matched`).
3. Alignment-probe strata recomputed from saved per-query records (`revision_probe`).
4. Expanded Wikidata and unified latency results (`revision_wikidata`, `revision_latency`).

All tests, intervals, and effect sizes are stored in `results/STATISTICAL_RESULTS.csv`, `EFFECT_SIZE_RESULTS.csv`, and `CONFIDENCE_INTERVAL_RESULTS.csv`. Figures are generated by `FIGURE_GENERATION_CODE/make_figures.py`.

## 2. Main 500-query contrasts

For `ac1`, the full system scores 0.772 against 0.646 for real SPARQL, 0.544 for multilingual dense retrieval, and 0.400 for the legacy SPARQL-style baseline. Holm-corrected McNemar exact tests give:

- fair-baseline contrasts: p ≤ 3.2×10⁻⁸;
- `no_aligner` / `no_aligner_k6`: p = 7.85×10⁻⁴;
- all accuracy contrasts in the family: p < 10⁻³.

The earlier manuscript wording “all Holm-corrected p < 10⁻⁷” is therefore false and must remain corrected. Honest wording is “all p < 10⁻³, with fair-baseline contrasts p ≤ 3.2×10⁻⁸”.

## 3. Matched supervision isolates the LLM contribution

Under the same alignment table and all 500 queries:

- LLM ac1 = 0.772; deterministic traversal ac1 = 0.498.
- Difference = +0.274, paired bootstrap 95% CI [0.230, 0.318].
- 151 LLM wins vs 14 traversal wins; McNemar exact p = 3.39×10⁻³⁰; Holm p = 1.36×10⁻²⁹; OR = 10.79.
- `vic` difference = −0.014, CI [−0.038, 0.008], Holm p = 0.473: no evidence of a strict-evidence recall advantage.

On the 150 cross-lingual queries:

- ac1 = 0.433 for both systems; difference = 0; 0 discordant pairs; p = 1.
- This is **not** an equivalence result. With zero discordant pairs, McNemar has no evidence of difference, but equivalence would require a pre-specified margin and an equivalence test.
- `vic` = 0.827 vs 0.867; difference = −0.040, CI [−0.073, −0.013], Holm p = 0.043. This small advantage for traversal concerns evidence value coverage, not answer ranking.

Interpretation: the LLM's surviving full-benchmark advantage is planning/predicate selection on in-language queries; its cross-lingual accuracy advantage disappears once alignment supervision is matched.

## 4. Alignment-exposure probe

Recomputed from `probe_per_query.csv` and stratified by category:

| Stratum | n | Observed Hits@1 | Exact 95% CI |
|---|---:|---:|---|
| cross-lingual, gold URI in prompt | 130 | 0.500 | [0.411, 0.589] |
| cross-lingual, gold URI absent | 20 | 0.000 | [0.000, 0.168] |

The 0/20 result must be reported as “no success observed in 20 queries”, not “capability is exactly zero”. The exact interval allows a true success probability up to about 16.8%.

The 16 one-hop and 150 two-hop unexposed queries are not part of this headline stratum; mixing them would change the estimand. The consolidated file keeps them as separate rows.

## 5. Wikidata transfer check

On the expanded 184-query authentic Wikidata benchmark:

- one-hop ac1 = 1.000 across all supervision groups (n=114).
- cross-lingual no-supervision ac1 = 0.029 (2/70); both successes are surface-identical zh/en labels (`Megaupload`, `YouTube`).
- cross-lingual matched ac1 = 0.700 (49/70), exactly corresponding to the train-pool alignment coverage.
- held-out cross-lingual non-oracle ac1 = 0/21, exact CI [0.000, 0.161].
- oracle ac1 = 1.000.

This supports alignment-coverage diagnosis, not a claim about real cross-graph alignment or LLM capability.

## 7. Reporting rules for the manuscript

- Use paired tests for paired queries; never treat systems as independent samples.
- Carry Holm correction when reporting the family of accuracy contrasts.
- Report effect sizes together with CI, not alone. Odds ratios can look large when outcomes are common; the `odds_to_r` rows are descriptive transforms, not new tests.
- Avoid “no difference” or “equivalent” for the 0-discordant cross-lingual pair; say “no observed difference under matched supervision”.
- Keep “serial service time” distinct from loaded response time and throughput.
